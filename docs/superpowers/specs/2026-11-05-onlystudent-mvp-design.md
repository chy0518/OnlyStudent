# OnlyStudent 最小 MVP 设计

**日期：** 2026-11-05

**状态：** 待产品方确认

## 1. 意图与背景

OnlyStudent 是连接教师和学生的一站式教育服务平台。本次工作从空目录开始，交付一个能在本机通过 Docker 独立启动、在浏览器中访问的 Web MVP，用一条完整但有限的流程验证产品：不同身份登录、浏览/购买网课、进入班级并完成教学活动、查看个人余额。

平台首先服务两类账号：教师发布和管理教学内容，学生选课并在班级学习。管理员仅用于演示数据和基础管理，不作为首版重点运营后台。

## 2. 目标

- 使用 React + TypeScript 前端、NestJS + TypeScript API，并保持前后端分离。
- 使用 PostgreSQL 保存业务数据、Redis 支持缓存/会话或后续队列扩展、MinIO 保存课程和班级文件。
- 账号带有固定角色；登录后自动获得该角色允许的功能和导航，不需要手动切换身份。
- 提供预置的管理员、教师、学生演示账号以及可见的演示课程、班级和余额。
- 免费课可直接加入；付费课使用本地模拟余额购买。充值同样只增加测试余额。
- 使用独立命名的 Docker Compose 项目、网络和数据卷；不复用、修改或删除电脑上已有的容器、网络、镜像或卷。
- 一条命令构建并启动，用户能通过 `http://localhost:5173` 打开网站。

## 3. 非目标与边界

- 不接入微信、支付宝、银行卡或任何真实支付渠道；不处理真实货币或订单回调。
- 不做直播、即时聊天、论坛、通知推送、复杂课件播放器、错题智能分析、排课、优惠券或多机构管理。
- 视频首版以可访问的课程/班级资料链接和演示资源为主，不做转码、加密、防下载或 CDN。
- 不实现生产级账号注册、找回密码、短信/邮件验证、第三方登录、审计合规和高可用部署。
- 管理员只提供最小查看/初始化入口，不扩展为完整运营后台。

## 4. 已确认的产品决定

- 用户角色跟随账号：教师和学生功能在班级中不同，登录后自动按角色生效。
- 首版将预置管理员账号，以及至少一个教师和一个学生账号，方便本机验收。
- 充值和课程付费均模拟完成，但必须抽象支付服务接口，使未来替换真实支付通道不会改动课程购买业务。
- 技术路线选择 React + TypeScript / NestJS + TypeScript。

## 5. MVP 用户体验与功能范围

### 5.1 全局体验

- 登录页：使用预置账号登录；显示可直接用于演示的账号信息。
- 应用框架：左侧固定菜单为“首页、网课、班级、我的”，顶部显示当前登录用户、角色和退出入口。
- 页面和按钮按登录用户角色显示；后端同时校验 JWT 与角色，前端隐藏不是权限控制的唯一依据。

### 5.2 首页

- 展示推荐网课卡片：封面、标题、教师、价格、已购/免费状态。
- 展示已关注教师或已加入课程的最新动态（首版由教师发布课程/班级公告产生）。
- 点击课程进入课程详情；点击动态进入关联课程或班级。

### 5.3 网课

- 学生可浏览课程列表、按免费/付费筛选、查看课程详情和教师信息。
- 学生可免费加入免费课，或从模拟余额购买付费课；购买生成订单和余额流水，课程状态变为已购。
- 教师可查看自己发布的课程，并创建/编辑课程的基础信息、价格和章节资料。
- 课程资料文件经 API 上传至 MinIO，数据库仅保存对象键、名称、类型和访问元数据。

### 5.4 班级

- 教师可创建班级，查看班级学生，发布公告、课次/资料、一个简答或选择题练习，以及作业。
- 学生可看到自己加入的班级，阅读公告和资料，完成练习并提交作业文本/附件；可查看自己的提交状态与练习结果。
- 班级成员关系首版可由教师通过演示数据建立；同时提供学生通过班级邀请码加入的最小入口。
- 教师能查看学生的提交与答题结果，但首版不做批量评分、自动批改以外的复杂评分流。

### 5.5 我的

- 查看并更新有限的个人资料（昵称、头像占位、个人简介）。
- 查看模拟余额、充值入口、最近余额流水和最近课程订单。
- 充值调用统一的支付创建接口的模拟实现，成功后更新余额与流水。

### 5.6 管理员

- 管理员可登录并进入一个最小管理页，查看用户、课程和班级的汇总数量。
- 管理员不在首版承担内容审核、封禁、退款等运营流程。

## 6. 角色与权限

| 资源/动作 | 学生 | 教师 | 管理员 |
| --- | --- | --- | --- |
| 浏览课程、加入/购买课程 | 是 | 可浏览 | 可浏览 |
| 发布/编辑自己的课程 | 否 | 是 | 可查看 |
| 创建/管理自己的班级 | 否 | 是 | 可查看 |
| 访问已加入班级的资料、练习、作业 | 是 | 自己班级的管理视图 | 可查看 |
| 提交练习和作业 | 是 | 否 | 否 |
| 模拟充值、订单/余额明细 | 是 | 是 | 可查看 |

## 7. 系统设计

### 7.1 服务划分

```text
浏览器 ──> React Web（5173） ──HTTP/JWT──> NestJS API（3000）
                                               ├─ PostgreSQL：用户、课程、班级、订单等
                                               ├─ Redis：缓存与未来任务队列的基础设施
                                               └─ MinIO：课程/班级资料和作业附件
```

前端采用 Vite + React Router + TypeScript，按页面域组织 API 调用和 UI。后端采用 NestJS 模块：认证与用户、课程、班级、练习与作业、钱包与订单、文件、管理。ORM 使用 Prisma，并以迁移文件管理 PostgreSQL schema。API 使用 REST 与 OpenAPI/Swagger 文档，错误格式一致。

### 7.2 核心数据

- `users`：账号、密码哈希、角色（`ADMIN` / `TEACHER` / `STUDENT`）、资料与余额。
- `courses`、`course_sections`、`course_resources`：课程、章节与 MinIO 文件引用。
- `course_enrollments`：学生拥有或免费加入的课程。
- `classes`、`class_members`、`class_announcements`、`class_resources`：班级与成员、公告和资料。
- `quizzes`、`questions`、`quiz_submissions`：练习、题目和学生作答结果。
- `assignments`、`assignment_submissions`：作业与提交。
- `orders`、`wallet_transactions`：模拟支付订单与不可变余额流水。
- `teacher_follows`：学生关注教师，用于首页动态筛选。

### 7.3 认证与支付抽象

登录成功后 API 签发 JWT，前端使用受保护路由，所有领域写操作由 API 的角色守卫和“资源所有者”校验保护。

支付模块定义 `PaymentProvider`：创建支付、查询结果、处理成功结果。MVP 的 `MockPaymentProvider` 立即以内部成功结果完成充值/购买，并在事务中写订单与余额流水。未来真实支付提供者仅实现该接口并使用回调更新订单状态；课程购买服务保持不变。

### 7.4 文件存储

MinIO 使用独立 bucket，例如 `onlystudent-mvp-files`。API 负责上传鉴权、对象命名和签名下载 URL；浏览器不持有 MinIO 管理凭据。数据库保存元数据和对象键。开发种子数据可创建少量文本/图片类占位资源，避免依赖外网。

## 8. Docker 与本地运行边界

- 使用 `compose.yaml` 的项目名 `onlystudent-mvp`，并设置专属网络 `onlystudent-mvp-network`、卷 `onlystudent-mvp-postgres-data`、`onlystudent-mvp-redis-data`、`onlystudent-mvp-minio-data`。
- 服务名为 `web`、`api`、`postgres`、`redis`、`minio`；数据库服务不暴露到宿主机，只有 Web 和 API 暴露必要端口。
- 预计入口为 Web `5173` 和 API `3000`。若本机端口被占用，用户可在 `.env` 中调整映射端口，容器内部连接保持不变。
- 所有镜像、容器、网络和卷限定在该 Compose 项目；停止命令仅作用于 `onlystudent-mvp` 项目。说明文档不会建议使用全局清理 Docker 的命令。
- 初始化迁移、MinIO bucket、演示账号与课程/班级数据均由项目自己的启动/种子流程完成。

## 9. 验收流程

1. 运行项目文档提供的 Docker Compose 命令，访问 `http://localhost:5173`，看到登录页与演示账号。
2. 以学生身份登录：看到首页课程/动态，购买一门付费课、余额减少且订单存在；加入班级、阅读资料、提交练习/作业；在“我的”完成模拟充值。
3. 以教师身份登录：创建课程或编辑已有课程；创建/管理班级，发布公告、资料、练习和作业，查看学生提交。
4. 以管理员身份登录：查看最小汇总页。
5. 重启同一 Compose 项目后，PostgreSQL 与 MinIO 的演示过程中产生的数据仍在独立卷中。
6. API 自动化测试覆盖：角色越权拒绝、免费加入、模拟充值、模拟购买扣款、班级成员访问、作业/练习提交；前端至少有关键页面和角色导航的测试。

## 10. 曾考虑的实现路线

1. **React + TypeScript / NestJS + TypeScript（已选择）**：前后端共享类型和语言，便于快速构建清晰模块、权限和接口，适合本项目从 MVP 向复杂业务演进。
2. **Vue 3 / Spring Boot**：适合长期企业级复杂业务，但首版的样板代码、构建和配置量更大。
3. **Vue 3 / FastAPI**：原型速度高，但前后端双语言会增加小团队的维护切换成本。

选择第一条路线是为了以最少的技术切换实现可本地演示的完整闭环。

## 11. 留给实现者的技术决定

- 选择简洁、可访问且维护成本低的组件/样式方案；不依赖付费 UI 服务。
- 使用常见的密码哈希与请求验证方案，密钥通过本地 `.env` 示例文件配置，不提交真实秘密。
- 在不影响核心验收流的前提下，决定具体的缓存键、API 分页细节和演示资源样式。
- 优先让 Docker 冷启动可靠；可根据构建体积和启动速度选择开发镜像或多阶段生产镜像。
